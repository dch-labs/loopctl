## [Unreleased]

### Added
- `ToolRegistry::all_tools()` — every registered tool as `Vec<&dyn Tool>`, in registration order (an overwriting same-name registration keeps the tool's original position; a parallel name-order index preserves the order while the map stays the O(1) lookup). Includes concurrency-unsafe tools, unlike `concurrent_safe_tools()` — hosts walking the registry for per-tool fragments (a system-prompt builder collecting each tool's prompt section) no longer need the `tool_names()` + `get()` N-lookup workaround. Pinned by the four `all_tools_*` registry tests (`src/tool/registry.rs`).
- `RunConfig::with_parallel_dispatch(ParallelDispatchConfig)` — the one way a host opts a run into parallel tool dispatch: `RunConfig` is `#[non_exhaustive]` and previously exposed no setter, so `ParallelMode::Parallel` (implemented, documented, defaulted off) was unreachable from outside the crate — a documented knob no downstream caller could turn on. Found while stress-driving the breaker gate's single-flight guarantee under concurrent dispatch; that guarantee is now pinned end-to-end by `concurrent_calls_share_one_recovery_probe` (a concurrency-safe slow-failing tool, a two-call message in one wave: the trip plus exactly one probe executes, the in-flight twin is refused).
- `SafetyShieldMiddleware` (`loopctl::middleware`, `tool_shield` feature) — the missing wire for the tool-safety shield: consults the configured [`ToolSafetyShield`] before every watched dispatch, turns a `Block` decision into a soft error naming the shield's reason (the model sees the refusal and adapts; the run continues), emits a `Warn` decision's reason and category as a tracing warning while the call proceeds (advisory — the warning was previously computed and discarded, with no log line and no result trace), and feeds every call it admits (executed or served from an inner cache) back via `record_invocation` so multi-call combination rules (`curl` then `| sh`) fire across turns. Opt-in via pipeline installation — a default loop is unchanged. The middleware also provides the `ShieldContext::recent_calls` snapshot the field always documented — `(tool, turn)` pairs of the most recent 20 dispatched calls, so history-less shields get a recency view without keeping one (blocked attempts never enter it, and the window bounds the per-evaluation snapshot to constant cost over a long session — pinned by `the_recent_calls_snapshot_is_bounded_to_a_recency_window`, fail-first: the 22nd call's evaluation saw all 21 prior calls instead of the retained 20). Blocked attempts never feed the shield's history (only admitted calls are recorded) and carry the model-issued call id (the engine stamps it regardless; direct `ToolPipeline::invoke` callers keep the correlation), and repeated shield refusals count as failures toward the tool's circuit breaker — once it opens, the engine's breaker gate refuses first, so the model sees "temporarily unavailable" rather than the shield's reason. The shield evaluates the tool name as it reaches this middleware's layer — install it inside (registered after) any middleware that rewrites `ctx.tool_name`, so aliases are evaluated under the name the registry executes; a rewriter placed inside the shield redirects after evaluation and the aliased call runs unshielded (pinned by `a_rewritten_watched_tool_is_shield_evaluated`); for the same behavioral reason install it outside `MemoizingMiddleware` — a repeat served from an inner cache is still evaluated and recorded, because the repetition dimension scores the model's behavior rather than the tool's execution (pinned by `a_cache_hit_is_still_shield_recorded_when_the_shield_sits_outside_memoize`), and the empty watched set skips the middleware entirely (pinned by `a_shield_watching_nothing_is_never_consulted`); `UnixShield`'s watched set now unions the combination-rule trigger tools, so a combination-only shield (blank pattern table plus rules) is actually consulted — previously it named no tools and its rules were dead (pinned by `a_combination_only_shield_still_names_its_trigger_tools`, fail-first: the set was empty). The post-call record (`record_invocation`, `recent_calls`) describes the call as the middleware evaluated it — a name or input rewritten by an inner layer does not leak into the shield's history. In the same change, `UnixShield`'s substring scoring gained token-boundary discipline and honest advisory scores: patterns match on word boundaries where the pattern's own edge is a word character — both the single-tool patterns and the combination-rule triggers; a symbol edge (`|`, `/`) cannot be extended into a longer token and carries no adjacent constraint, so `/etc/` matches `/etc/passwd`, `.ssh/` matches `.ssh/authorized_keys`, and the pipes match the no-space `cmd|sh` (a uniform boundary rule had silently missed all three — the path patterns' real targets and the natural compact pipe), while word-character edges keep their discipline (`| sh` does not match `| sha256sum`; `curl` matches `curl http…` but not `mycurlcmd`), and an empty or whitespace-only pattern matches nothing — a needle with no edges would otherwise match at every position and score every call of the tool, and an empty combination-rule substring would advance on every call to the named tool (pinned by `an_empty_pattern_matches_nothing`, fail-first: an empty 0.9 pattern scored every input), and the bare `curl`/`wget` patterns dropped to 0.3 advisory (`curl_usage`/`wget_usage`) — plain `curl --version` and `wget --version` were previously blocked outright, while `curl … | sh` and `wget … | sh` remain blocked by the `| sh` pattern and the combination rule — and the compact pipe-to-shell spelling is a pattern of its own (`|sh`, same 0.8, boundary-checked so `|sha256sum` stays untouched; pinned by `the_compact_pipe_to_shell_form_scores_and_a_checksum_pipe_does_not` and covered by the oracle property). Command polymorphism cannot bypass the patterns: matching runs on a normalized view (lowercased, whitespace runs collapsed, JSON-escaped whitespace folded), and the split/long flag spellings of recursive delete (`rm -r -f`, `rm --recursive`) are patterns of their own — previously `rm  -rf  /` (double space), `RM -RF /`, and the flag spellings all sailed through the 0.9 pattern as `Allow`. Pinned by `command_polymorphism_does_not_bypass_the_patterns` and `symbol_edged_patterns_match_their_real_targets` (fail-first: the no-space pipe scored the advisory 0.3); the oracle property's mutations include space deletion and its expectation is the max over the full pattern table, mirroring the scoring. Repetition amplifies risk but cannot block alone (the multi-turn dimension caps at 0.30 of the block threshold's 0.7), so a session of repeated benign calls keeps executing — pinned by `repeated_benign_usage_warns_but_never_blocks`. Pinned by `a_block_scored_input_does_not_execute_with_the_middleware_installed`, `benign_curl_invocation_is_not_blocked`, `benign_wget_and_checksum_pipes_are_not_blocked`, `curl_piped_to_sh_is_still_blocked`, `combination_triggers_respect_token_boundaries_too`, `single_tool_scoring_agrees_with_the_boundary_oracle`, `shield_middleware_records_invocations`, and `the_download_then_execute_sequence_blocks_on_the_second_call` (`tests/unwired_subsystems.rs`).
- `CompactionContext::instructions` + `CompactionContext::additional_context` — pre-compact hook guidance threaded to the compactor: the driver keeps the hooks' merged `new_instructions`/`additional_context` (previously only the abort bit was read) and `ContextManager::compact_with_reason` takes them, so LLM summarizers can consume the hook's guidance. `compact_manual` passes empty guidance. **Breaking:** `compact_with_reason` takes two new parameters. The pre-compact hook context's `trigger` is now derived from the compaction reason (`Manual` reaches hooks as `Manual`) instead of hardcoded `Auto`, and the executor chains hooks: a later hook's `custom_instructions` now carries the accumulated instructions of earlier hooks, as the field always documented. Pinned by `hook_instructions_reach_the_compactor` and `compact_trigger_maps_every_compaction_reason`.
- The engine consults the tool-health breaker before dispatch: with a `ToolHealthRegistry` configured, a tool whose circuit breaker is open is refused with a soft error ("tool temporarily unavailable: circuit breaker open") instead of executing — the model sees the refusal and the run continues. The gate grants through the breaker's mutating [`allow_request`], so it enforces exactly the breaker's decision (a closed breaker dispatches even when the health score is poor — the score never blocks, only the breaker does) and keeps recovery single-flight (an expired cooldown grants one probe; concurrent calls during the probe are refused). A new registry-level `ToolHealthRegistry::allow_request` mirrors the breaker method for the gate. The gate consults the *requested* name's breaker — renaming happens inside the pipeline (middleware rewrite `ctx.tool_name` on the way to the core), so a host pipeline that renames diverges the gate's key from the resolved name health recording uses; the two key spaces are identical for every non-renaming pipeline, and no in-tree middleware renames (pinned by `the_gate_keys_on_the_requested_name_across_a_renaming_middleware`). Pinned by `an_open_breaker_stops_dispatching_the_tool`, `a_closed_breaker_with_a_poor_score_still_dispatches`, `breaker_retrips_on_a_failed_probe_then_closes_on_success`, and `unknown_tool_calls_do_not_create_ghost_breakers` (`tests/unwired_subsystems.rs`).
- `redaction` feature + `RedactingMiddleware`/`SecretPatternSet`/`SecretPattern` (`loopctl::middleware`) — scrub secrets from tool output post-execution: a configurable set of named regex patterns (curated defaults cover `Authorization: Bearer` headers, `api_key=`-style tokens, AWS access-key IDs, PEM private-key blocks, GitHub/GitLab PATs) plus a Shannon-entropy heuristic (≥32-char tokens at ≥4.5 bits/byte become `[REDACTED:high_entropy]` — hex hashes stay visible at their 4.0 ceiling). Every match becomes `[REDACTED:<kind>]`; image parts and non-text content pass through untouched; `is_error` and `DisplayHint` are preserved (advisory only — loop semantics unaffected). Extend with `SecretPatternSet::with_pattern`, disable the heuristic with `with_entropy_heuristic(false)`. Pulls `regex` only under the feature; `default = []` unchanged. Pinned by the tests in `tests/redacting_middleware.rs`.
- `ToolOutput::with_payload(ToolContent)` — fluent payload replacement on the `#[non_exhaustive]` `ToolOutput`, making multipart outputs constructible outside the crate (`ToolOutput::text` only builds plain text). Runnable doctest included.
- `BareLoop::with_temp_dir(base)` — override the base directory under which the per-session temp subdir is created (`{base}/loopctl-{session_id}/`; an empty path opts out). `BareLoop::with_managed_temp_disabled()` — opt out of managed temp entirely: tool contexts get the process-wide temp and dropping the loop removes nothing.
- `DetectionManager::consume_pending_loop_stop` — the engine calls it at every run end (both the clean and the failing path): when the loop window holds a pattern at or over `stop_threshold` that the run never fired (the run went terminal after its last dispatch), the window is cleared, mirroring the consumption a fired stop performs — otherwise the *next* run's first dispatch is killed by repetitions it never produced. Below the stop threshold nothing is cleared (sub-threshold history may still warn); convergence state is untouched (cross-run terminal streaks are load-bearing for the opt-in `Stop`/`AskUser` actions).
- `CircuitBreakerConfig::probe_timeout` (+ `ToolCircuitBreaker::with_probe_timeout`) — how long the single `HalfOpen` probe may stay in flight before the breaker gives up on it. A probe whose result never arrives (cancelled dispatch, dead task) previously stranded the breaker in `HalfOpen` forever — nothing records, so nothing closes or reopens it; after the timeout `allow_request` re-arms the `Open` cooldown and a later request probes again. Defaults to 30s (`new` defaults it to the recovery duration). The probe is lease-like: availability queries treat an expired probe as re-armed (recovering without needing a dispatch to trigger the re-arm), a result arriving after expiry no longer closes the breaker (it re-arms recovery, since it describes a probe the breaker has already abandoned), a call arriving after the expiry-anchored cooldown grants a fresh probe in the same call (the pure availability oracle and the mutating call agree at every instant), `0` disables the lease (a slow probe's success still closes), and the registry's availability reads, `would_be_half_open`, and `state_label` are all expiry-aware — a stranded probe can no longer wedge a tool's routing or report `half-open` during what is functionally an open cooldown.
- `LoopDetector::max_operation_count` — threshold-free companion to `LoopStatus::repetition_count`: the live maximum occurrence count in the window *below* the loop threshold too, so streak telemetry can watch a potential loop build up before it trips.
- `MockApiClient` now implements the `*_with_options` methods: a per-request `model` override is honored on the streaming path (the response's `MessageStart` names the routed model — the mock's stand-in for the wire-level switch, so fallback-routing tests observe the routing; the non-streaming response carries no model field, so the override is accepted there without an observable effect), while `response_format` and `tool_constraint` are rejected loudly (the mock implements neither).
- `DetectionManager::check_loop_pattern` (and `check_convergence_pattern`) — the loop-only (convergence-only) pattern as pure queries over the recorded state, the read side of `record_operation` / `record_response`. Dispatch pre-checks use the loop one, so a step examined twice is counted once. Both respect their `enable_*` flags.
- `RequestOptions::model` + `RequestOptions::with_model(.)` — a per-request model override honored by all three providers (OpenAI and Anthropic replace the request body's `model` field; Gemini, which carries the model in the URL path, builds the URL from it). The client's own model is untouched — concurrent loops over one shared client cannot cross-wire their models — and requests without an override are byte-identical to before.
- `LoopMachine::set_context_tokens(tokens)` — a driver-fed context estimate. The driver measures the payload the provider would receive (`count_context`, preferring the manager's counter, plus the measured per-request overhead) whenever it grows outside a model response — after `accept_input` at run start, after `tool_results` in the dispatch path, and before a model call carrying fresh transients (contributors, memories) — so the machine's compaction trigger sees the true size of what the next request would carry instead of the zero `accept_input` resets to. Estimate-only: no state transition, no effect once terminal.
- `LoopMachine::compaction_noop(tokens_before, tokens_after)` — a second compaction feed method for passes that changed nothing (no compactor ran, a pre-compact hook vetoed, or the compactor returned the conversation unchanged). Unlike `compaction_result`, it leaves the committed history and the pending buffer untouched and adopts `tokens_after` as the current context size. Both compaction feeds compare the driver's measured pre-pass and post-pass token counts: when nothing was shaved off, the machine terminates the run with `ContextExceeded` instead of trusting an estimate recorded at compaction-request time (which could be stale — set before the last turn's tool results, or zero at run start). Alt drivers servicing `MachineStep::Compact` should pass both measurements from one counter.
- `McpToolProvider::with_call_timeout(Duration)` — a per-call budget for every adapted tool's `tools/call` round-trip (default 60s). A call that exceeds it resolves to a *soft* error result naming the tool and the budget, so a wedged MCP server costs one tool result instead of hanging the agent loop indefinitely. Updates already-discovered tools and applies to later refreshes.
- MCP server adapter (`McpServerAdapter`) — serve a loopctl `ToolRegistry` over MCP (stdio), consumable by any MCP client. `McpServerAdapter::new(registry, ctx, name, version)` + `serve_stdio` implements `ServerHandler` (`list_tools` → `all_schemas`, `call_tool` → `Tool::call`). Served calls are raced against the request's cancellation token: an already-cancelled request resolves to a cancelled result without invoking the tool, and a client cancel (`notifications/cancelled`) or disconnect drops the in-flight tool future and resolves to a cancelled tool-level result — a wedged tool no longer leaks a task per call (tools must be cancellation-safe, the same contract the engine's dispatch path imposes). `list_tools` forwards each tool's `is_read_only` as the MCP `annotations.readOnlyHint` (with `destructiveHint: false`); tools whose input schema does not compile as JSON Schema — malformed keywords, uncompilable regexes, dangling or external `$ref`s (external references are refused, never fetched) — or is not object-typed are omitted from the listing with a warning rather than advertised with a schema strict clients may reject (the `mcp` feature now pulls `jsonschema` for this check); unknown tool names return a `METHOD_NOT_FOUND` protocol error listing the registered names; empty descriptions are omitted rather than sent as `""`. Tool names are forwarded verbatim — the MCP spec recommends `^[a-zA-Z0-9_-]{1,64}$` and conforming names are the embedding application's responsibility (documented in the module docs). Transport-agnostic: `serve(impl IntoTransport)` works for future HTTP/SSE. The module promoted to `mcp/{convert,server}.rs` with symmetric inbound/outbound converters co-located. Example at `examples/mcp_server.rs` (echo + failing tool, Ctrl-C → graceful cancel; includes a piped JSON-RPC acceptance recipe).
- MCP transports (stdio + Streamable HTTP/SSE) — `McpClient::stdio(command)` spawns an MCP server as a child process over stdio; `McpClient::http_sse(endpoint)` and `McpClient::http_sse_with_client(endpoint, reqwest::Client)` connect via the Streamable HTTP transport (rmcp handles `Mcp-Session-Id`, JSON-vs-SSE response splitting, and DELETE-on-close). `McpClient::reconnect(&StreamRetryConfig)` re-establishes a dropped connection using the crate's existing backoff strategy (the one retry strategy for the crate, not a second one). New public `CommandSpec` describes what to spawn. A stdio example server ships at `examples/mcp-stdio-server.rs` for transport testing. The `mcp` feature now enables `streaming` (for `StreamRetryConfig`) and `reqwest` (for the HTTP client); `default = []` is unchanged.
- `mcp` feature + `loopctl::mcp` module — adapt any MCP server's tools as loopctl `Tool` implementations. New public types: `McpClient` (a connected client handle), `McpToolProvider` (discovers a server's tools and registers them into a `ToolRegistry`), `McpTool` (one server tool as a `Tool`), `McpError`. Real-server transports ship alongside (stdio child processes and Streamable HTTP/SSE — see the transports entry above); `McpClient::in_process` connects an in-process rmcp server for tests and bundled-server use. The optional `rmcp` dependency is pulled in only by the `mcp` feature (`default = []` is unchanged). A runnable end-to-end demo ships at `examples/mcp-adapter.rs` (`cargo run --example mcp-adapter --features mcp`).
- `LoopError::ToolRecoveryExhausted { tool, attempts }` — the driver now enforces `MAX_RECOVERY_ATTEMPTS` (5) as a hard ceiling. A recovery strategy that always returns `Retry` is stopped after 5 retries (attempt 6), returning this variant instead of looping forever.
- `RunConfig::memory_top_k` — configurable number of memory entries retrieved and injected per turn (default 3; was a hardcoded magic number).
- `MachineStep::CallTools { turn, calls }` — the machine now emits the 0-indexed turn number on `CallTools` (matching `CallLLM`), so both handlers source the turn identically from the machine rather than one reading a field and the other querying a counter.
- `loopctl::testing::EnvGuard` — a shared RAII guard for tests that mutate environment variables. `EnvGuard::acquire(&["VAR_A", "VAR_B"])` takes a crate-wide lock (parallel tests cannot interleave environment access), snapshots the named variables, and restores each to its prior value — present or absent — on drop, covering assertion failures and panics; `set`/`remove` mutate under the held lock and reject names that were not snapshotted, and a nested `acquire` fails fast instead of deadlocking. Usable from lib tests, integration tests, and downstream via the `testing` feature.
### Changed
- **Behavior change:** `ToolContext::temp_dir` is now per-session when the context is built by `BareLoop` — by default `{std::env::temp_dir()}/loopctl-{session_id}/` (`with_temp_dir` moves it under a caller-supplied base), materialised lazily on first tool dispatch and removed when the loop is dropped (best-effort: a missing dir is silent, another IO error logs one `warn!` and is swallowed — `Drop` cannot return errors). Previously the field was documented as per-session but actually held the process-wide OS temp, and nothing ever cleaned it — a slow disk leak for tools that spill results to temp. `BareLoop` now implements `Drop`; `into_machine()` still works (the machine is replaced out of the consumed husk, whose drop cleans the session temp — correct for checkpoint-and-resume). Migration: hosts that read `temp_dir` and assumed the process-wide path should call `with_temp_dir(base)` for a custom base or `with_managed_temp_disabled()` to restore the old behavior; the field doc now also distinguishes `temp_dir` from a host-owned session directory stored in extensions.
- **Behavior change:** `TokenSplitter` no longer splits a tool call from its result. A split point is now accepted only when it is pair-safe — no tool result in the kept portion references a call in the dropped portion, however far apart the two messages sit (a user message delivering tool results continues the same turn and is never a boundary; interleaved consecutive-user histories are covered too) — and when no pair-safe boundary exists at or before the target the whole conversation is preserved (`to_compact` empty) instead of falling back to an arbitrary index. Previously any assistant→user transition was a boundary, and the canonical call/result seam is exactly that transition — host code discarding `to_compact` sent providers a stranded result. Pinned by `token_splitter_does_not_separate_a_call_from_its_result` and `splitter_skips_boundaries_that_straddle_a_later_result` (`src/compact/truncating.rs`).
- **Breaking:** `GitExecutor::auto_commit_with_files` takes two new parameters, `tool_name: Option<&str>` and `session_id: Option<&str>`, supplying the values behind the `{{tool}}` / `{{session}}` commit-message expansion (see the Fixed entry below). Migration: direct callers pass `None, None` when the values are unavailable (the placeholders then expand to empty strings); the `AutoCommitHook` routes its tracked tool name and the run's session id automatically, and `GitExecutor::auto_commit` keeps its convenience shape.
- **Behavior change (window accounting):** the context estimate counts the whole request payload, not just history. The session system prompt and the advertised tool schemas are measured once per loop (with the same token counter, each counted as a synthetic message) and added to every estimate feed, and a turn's transient messages — context contributors, retrieved memories — are measured before the request goes out; if the payload then crosses the threshold or the emergency line, the turn defers to compaction instead of serving it unchecked. A deferred turn has not fired its observer events, and the retried turn re-consults contributors against the compacted history. Previously every window check was history-scoped: a request could exceed the provider's window by exactly the uncounted overhead — worst on small windows with a realistic tool-schema set — and a chunky contributor or memory injection rode entirely outside the check. Hosts measuring served requests take note: counting only `StreamRequest::messages` now understates the payload. Pinned by `served_requests_count_the_whole_payload` (fail-first: full-payload costs `[176, 255, 335]` against a 250-token window, the third request carrying 85 invisible tokens) and `a_transient_overload_defers_to_compaction_and_the_retry_proceeds` (the deferral mechanism itself: no phantom turn events, the retried turn re-consults contributors, its request served under the window — fail-first with the re-decision neutralized). The compaction serving a deferred turn reserves the transient budget: `ContextManager::compact_with_reason` takes a `reserved_tokens` parameter (**breaking** — a sixth argument; `compact_manual` passes `0`), subtracted from both the compaction target and the fit check, and the driver passes overhead plus the deferred turn's measured transients. Without the reserve, the first pass could compact to "fits the window" while ignoring the transients, the retry would defer again, and the idempotent second pass would dead-end on `ContextExceeded` despite a fitting layout existing — pinned by `a_deferred_compaction_reserves_the_transient_budget` (fail-first: the unreserved pass dead-ended at `used == limit`). The reserved fit check's `ContextOverflow` reports the payload including the reserve — a history-only `tokens_used` read as a pass against the full window (175 under a limit of 300) while the reserve forced the failure; the typed `ContextExceeded` hosts see now explains itself (pinned by `a_reserved_overflow_reports_payload_comparable_numbers`, fail-first). A compactor that fails outright reports the same payload-comparable usage (history plus reserve — pinned by `a_failing_compactor_reports_payload_comparable_usage`), and the engine logs the compactor's own error before mapping the failure to `ContextExceeded`, so a broken summarizer no longer masquerades as a bare overflow.
- **Behavior change (truncation strictness):** a stream that ends without the provider's terminal signal is no longer a completed turn. Three layers changed together: the emitters no longer synthesize a terminal `MessageStop` on a bare EOF (Anthropic now emits the stop only for a real `message_stop` event, Gemini only after a `finishReason` chunk, OpenAI only after a `finish_reason` or the `[DONE]` sentinel — the reader tracks the sentinel via `SseReader::done_marker_seen`), and `StreamHandler::stream_turn` treats end-of-stream without `MessageStop` as a *transient* truncation failure routed through the retry ladder — retried within budget and, at exhaustion with the fallback enabled, handed the last-chance non-streaming request, otherwise failing with `InitFailed` naming the truncation. Previously a connection cut mid-generation (clean FIN behind a proxy) was normalized into an apparently well-formed turn: truncated text returned as the completed output and the breaker credited with a success — the same masquerade class the mid-stream error fix closed for error chunks, now closed for silent cuts. Custom `ApiClient` implementations that end streams without `MessageStop` will now see retries followed by a typed failure; emit the terminal event (as every first-party emitter and `MockApiClient` does).
- **Behavior change:** the `ApiClient` trait's default `stream_messages_with_options`/`create_message_with_options` implementations now reject every option field they cannot forward — `response_format`, `tool_constraint`, and the per-request `model` override — with an `ApiError::config` error, instead of silently delegating to the options-less method when only `response_format` was unset. A silently dropped `model` override served a different model than the one the fallback breaker routed and reported (the exact failure the per-request fallback routing exists to prevent) for every non-overriding client — before this change the crate's own `MockApiClient` was among them (see Added: it now honors the override); such clients now fail loudly, forcing the override. The three first-party providers override both methods and are unaffected.
- **Behavior change:** a `ToolConstraint::Grammar` request to the Anthropic or Gemini client now fails fast with an `ApiError::config` error (both APIs have no grammar-constrained tool decoding; previously the grammar was silently dropped and the request sent unconstrained). Only OpenAI-compatible endpoints consume grammars (`guided_json`).
- **Behavior change:** `OutputLimitMiddleware` now counts its truncation marker inside the budget — a cut text part is exactly `max_chars` long (kept text + `
[truncated]`, the marker alone when the budget is smaller than the marker), and multipart parts that get zero remaining budget are emptied instead of each growing a fresh marker (a 50-part payload under a tiny cap previously emitted ~600 characters of markers, structurally exceeding the cap the middleware exists to enforce). `OutputLimitMiddleware::new(0)` now disables the middleware entirely (the crate-wide zero-disables sentinel) instead of reducing every output to a marker.
- **Behavior change:** `CircuitBreakerConfig::failure_threshold: 0` now disables tripping (failures are counted for telemetry; the breaker never opens) — the crate-wide zero-disables sentinel, previously inverted (`0` tripped on the *first* failure).
- **Behavior change:** `StreamTimeoutConfig::validate` rejects `Duration::MAX` for `total_stream_timeout` — the value silently disables the total deadline, both backoff clamps, *and* the non-streaming fallback deadline via `checked_add` overflow. `passthrough` still constructs its config directly (documented opt-in). `with_timeout_config` substitutes only the invalid fields with defaults — infinite (`Duration::MAX`) event timeouts are substituted like zero ones, and the ordering rule runs once after substitution so the sanitized result always satisfies every `validate` rule — preserving the caller's valid customizations instead of discarding the whole config.
- **Behavior change (engine detection defaults):** when the configured `ToolSignature` extracts an empty primary parameter (the default `NoOpToolSignature`'s blind spot), the engine records the operation under a canonical-JSON rendering of the tool input. Previously two calls of one tool with *different* inputs but byte-identical outputs (the same file content read from two paths, `git status` on an unchanged tree) collapsed into one operation and counted as repetition; now only identical inputs repeating is flagged. A signature that does extract keeps full control of the key.
- **Behavior change:** a memoize cache hit now preserves the cached call's `duration` instead of zeroing it, so `ToolStats` averages track the real tool latency rather than a zero-cost lookup; and engine health statistics are keyed on the executed (resolved) tool name when a routing middleware renamed it — the same key space `VerifyMiddleware` matches on.
- **Behavior change:** `RequestOptions::with_model` ignores an empty or whitespace-only name (the override stays unset), mirroring the client builders' rejection of nameless models; and `AnthropicClientBuilder::build` rejects `max_tokens: 0` (the Messages API requires ≥ 1 — previously a guaranteed server 400).
- The rate-limit retry ladder's docs are reconciled with the executed behavior: under the default config (`fallback_after_retries: 3 < max_retries: 5`) the ladder's only terminal outcome is `Escalate` (fail the turn; the engine records it against the circuit breaker, which routes subsequent turns to a fallback model) — a same-model non-streaming request is deliberately not attempted because rate limits are charged against the model's quota. `HardStop` (and its last-chance non-streaming fallback) is reachable only when `fallback_after_retries == max_retries`. Previously one doc block promised a "symmetry fix" (both exhaustion paths routing through the fallback) that the default config never delivered.
- **Breaking:** `LoopError` gains a `UserInputRequired` variant. Exhaustive matches on `LoopError` must add this arm. The same collision between the thinking lane (index 1) and a second tool call (wire index 1) is closed with it.
- Lenient JSON extraction completes on mixed nesting: `extract_json_substring` now tracks independent `{` and `[` depths instead of remembering only the outermost delimiter kind, so a fenced or prose-wrapped object containing an array — or an array containing objects — finally parses. Previously an inner closing delimiter of the other kind was treated as a mismatch and aborted the scan, so the exact `LlmReflector` failure-analysis shape (`{"is_recoverable":true,"correction":{"modified_input":{"path":["a"]}}}`) extracted as nothing and the structured-output rescue (the non-strict-mode path behind `ApiClient::extract_structured`) failed on every array-bearing payload. A closing delimiter that arrives while its own depth is zero still abandons the candidate (garbage stays garbage) and the scan resumes. The lenient parser's tests also lost their needless `openai`/`gemini` feature gates — the parser is core machinery and now runs its suite in the default build.
- `tighten_json_schema` no longer silently loosens schemas: its `required` rewrite overwrote the entry list with exactly the property key set, dropping author-declared entries that name keys enforced structurally elsewhere (`allOf`/`not`) — contradicting its own comment. `required` is now the union: pre-existing entries in their original order, then property keys not already listed.
- `Retry-After` is captured. Provider clients now read the header at HTTP time and classify 429/503/529 responses into `ApiError::RateLimit { retry_after }`, so the server-advised-delay machinery (`RateLimitConfig::respect_retry_after` / `max_delay`) actually receives the provider's guidance — previously the header was discarded with the response object and downstream code tried to parse the delay back out of a flattened `"HTTP 429: {json}"` string, which can never carry it; end-to-end through `StreamHandler`, the observed retry delay honors the header's 7s, clamped by `max_delay`).
- Authentication failures (401/403) surface as `ApiError::Auth` from all three providers and cost exactly one streaming attempt with no non-streaming fallback, instead of arriving as a flattened `Http` string that was retried four times.
- Mid-stream error events no longer masquerade as clean stops. Anthropic's `event: error` (for example an `overloaded_error` after generation began) is parsed (`/error/type` + `/error/message`) into a recorded terminal error, and the stream terminates with it instead of a synthetic `MessageStop`; Gemini's analogous top-level `/error` chunk terminates the same way (`/error/status` + `/error/message`). Previously both were silently dropped and a consumer could not distinguish an errored stream from a healthy truncated one.
- An HTTP 429 surfaced as `ApiError::Http` is classified `RateLimitKind::RateLimited` (and 503/529 as `Overloaded`) by `DetectedRateLimit::detect`, matching the variant docs — previously every Http-carried overload status was misattributed to `Overloaded`, so quota exhaustion showed up as provider overload in logs and metrics. The structured `RateLimit` variant gets the same status-based kind split.
- Outbound provider wire correctness (five fixes): the OpenAI converter no longer silently drops the text parts of a message that also carries tool results — they ride along as a trailing `user` message after the `tool` messages, matching what the Anthropic and Gemini converters already did; an empty tool slice serializes to *no* `tools` key in all three body builders (was `tools: []`, which Gemini answers with `400 INVALID_ARGUMENT` and strict gateways reject); the Anthropic `tool_result` block carries `"is_error": true` on failed tool dispatches so the model can tell failures from successes; `with_base_url` trims trailing slashes in all three clients, so `http://host:8000/v1/` joins to clean paths instead of `/v1//chat/completions`; the `zai` default-model doc now says `glm-4.7` (the constant was the deliberate bump, the doc lagged).
- Inbound provider wire correctness: a streamed Anthropic turn now reports real `input_tokens` — the emitter latches `message_start`'s `usage` (the only place Anthropic reports input counts on the streaming path) and the terminal `message_delta` merges the two reports by taking each field's max, so cost accounting, context budgeting, and fallback tripping no longer see zero prompt tokens and the streamed and non-streamed paths agree on every turn; the Gemini non-streaming path no longer leaks reasoning summaries into the visible answer (`thought: true` parts are excluded from text content, matching what the streaming accumulator's text lane yields); SSE `data:` lines without the optional space — spec-legal, and emitted by some third-party OpenAI/Anthropic-compatible servers — now parse in all three providers through one shared normalization helper (previously the payload was silently skipped, and in Anthropic's event pairing the whole event dispatched without its data), and spec-legal compact `event:` lines dispatch under their event type in the Anthropic reader (previously every event dispatched as unknown and the stream silently yielded nothing); a streamed Gemini function call without `args` carries `input: {}` like the non-streaming parser (was `null`, which broke tool executors that index into `input`) — an explicit `"args": null` normalizes to `{}` on both paths too, while a non-object `args` passes through verbatim so malformed wire stays visible, `sse_data_line_without_space_is_parsed` (one per provider file), and `sse_event_line_without_space_dispatches_the_event` + `streamed_turn_dispatches_compact_event_lines_over_the_wire` (compact `event:` form) and `function_call_with_explicit_null_args_normalizes_to_empty_object` (explicit-null `args`).
- A mid-stream total-stream timeout is no longer retried and re-reported as an init failure. `decide_transport_error` treats a `TotalTimeout` outcome as terminal — the non-streaming fallback runs when one is configured, otherwise the turn fails once, never a second streaming attempt against the already-spent budget — and the already-built outcome propagates verbatim with the real `events_processed` and `has_partial_data`, instead of being rewritten to a mislabeled `InitFailed` carrying a hard-coded zero and the previous attempt's stale partial flag. The fallback itself is reachable on these paths: it races one fresh `initial_event_timeout` budget instead of the already-expired streaming deadline (which would kill the request on its first poll), and an expiry caught between retries surfaces through the same terminal route on the retried attempt's first poll rather than failing the turn directly. `TotalTimeout::duration` now spans every attempt in the turn (the per-attempt start-instant shadow is deleted), so the reported duration approximates the configured `total_stream_timeout` rather than the last attempt's fraction of it.
- The error-body cap actually caps: non-2xx diagnostic bodies are read bounded (an 8 `KiB` ceiling, enforced by a `Content-Length` pre-check that refuses the body outright plus a streaming stop for chunked responses), so a misbehaving endpoint answering a failed request with a multi-gigabyte page can no longer make the client materialize it in full before truncation.
- The machine's context estimate is no longer zero at run start: the driver feeds `set_context_tokens(count_context(full_history))` right after `accept_input`, so the compaction trigger runs before a run's first model call. Previously a session whose *committed* history exceeded the context window (from prior runs, a host-seeded resume, or a `from_machine` checkpoint restore) sent its first request over-window before any check could run. The same measurement now also runs after tool dispatch: the estimate is refreshed the moment tool results are appended (`set_context_tokens` after `tool_results`), so one turn's tool output — however large — is visible to the compaction trigger before the next request. Landing that exposed a mock divergence: `MockApiClient` now streams tool-call arguments as an `InputJson` delta instead of embedding them in `PartStart`, matching how real providers stream — the accumulator never read PartStart-carried input, so mock-served tool input silently arrived empty. Note the accompanying policy change: a fresh input that itself crosses the threshold (or the 95% emergency line) now triggers compaction before its first request, where previously the check was blind until the first response. A successful run-start compaction folds the run's input into committed history before the run proves itself — a run that compacts at start and then fails leaves its input committed, the same commit-point property mid-run compaction has always had for pre-compaction content (failure does not undo a compaction pass). Pinned by `first_request_of_an_over_window_run_is_never_sent`, `tool_result_growth_alone_crosses_the_threshold`, and `run_start_compacts_at_the_threshold` (verified fail-first with the run-start feed neutralized).
- No-op compaction passes no longer report a hard-coded zero estimate or commit the in-flight run's pending messages. Previously the driver's no-manager, pre-compact-hook-veto, and `NoAction` paths returned `tokens_after = 0`, which blinded the machine's no-progress guard and reset its context estimate — the loop kept calling the provider with an over-window conversation until the turn budget was spent. Worse, feeding the uncompacted history back through `compaction_result` committed the current run's partial messages mid-run, so a later failure leaked the aborted run's prompt, tool calls, and results into committed history forever (`discard_pending` could no longer undo it). These paths now return the measured estimate (`count_context`) through an explicit no-op signal that leaves pending untouched; when compaction genuinely cannot reduce, the run terminates with a typed `LoopError::ContextExceeded`.
- A no-change compaction pass is no longer reported as `EnsureContextResult::Compacted`: `ContextManager` used to wrap any successful compactor outcome as `Compacted`, so short-but-over-threshold conversations fired `on_compaction` observers (and post-compact hooks) on every triggering turn with zero savings and identical messages, violating both contracts. Same-list/zero-savings outcomes now map to `NoAction`.rs).
- Census round 3 fixes (seven behavior changes, each pinned): a client that rejects `set_model` now rejects the whole `ModelSwitch::apply` — proceeding re-pointed the fallback manager at a model the client never adopted, and the per-request override would have served it anyway (`switch_model_unsupported_client`); a success recorded while the tool breaker is `Open` no longer closes it — such a success can only come from a call admitted before the trip, and recovery is decided by a probe (`a_stale_success_cannot_untrip_a_freshly_opened_breaker`); `ToolStats` duration accumulation saturates at `u64::MAX` instead of wrapping, as its doc always claimed (`duration_accumulation_saturates_rather_than_wraps`); `set_context_manager` syncs the session's `compact_threshold` alongside the window, so a host manager no longer triggers at ~6x the intended point (`set_context_manager_syncs_the_session_window_and_threshold`); a `response_format` with `strict: true` fails fast on the Anthropic and Gemini clients instead of being silently served non-strict (both `*_with_options` paths ×2); `on_fallback`'s `from` names the model that was actually serving (the routed model), not the client's; memoize stores invalidation paths taken from the same input its cache key was built from, not an inner middleware's rewritten copy. Dozens of census doc contradictions fixed alongside (discard-pending vs mid-run compaction commit point, `reset_all` scope, `recent_calls` watched-only, turn-start ordering, zero-value fallback knobs, threshold strictness, and more).
- `ContextOverflow::trigger` names the reason that actually triggered the failed pass: both error sites in `ContextManager::compact_with_reason` hard-coded `CompactReason::Manual`, so a threshold- or emergency-triggered compaction that could not fit reported `Manual` — contradicting the field's own doc, which describes `Emergency` semantics the hard-code made unreachable. Both sites now report the `reason` they were called with (pinned fail-first by the trigger assertion in `a_reserved_overflow_reports_payload_comparable_numbers`).
- The non-streaming fallback forwards the turn's `RequestOptions` and is bounded by the total-stream deadline (`StreamHandler::fallback_non_streaming`): it previously called `create_message` (dropping any configured `response_format`/`tool_constraint`) and raced only the cancel signal, so a hanging fallback request hung the turn.
- MCP `tools/call` round-trips are bounded by the new per-call timeout (see `McpToolProvider::with_call_timeout` above) — previously a wedged server hung the agent loop with cancellation as the only exit.
- Tool-result parts in a `CallTools` turn preserve **model request order** across preresolved (unknown-tool) and dispatched calls. Previously the turn's results were assembled as `[all preresolved, then all dispatched]`, which reordered the parts the model saw relative to the calls it made. Provider-safe in practice (providers match by `tool_call_id`, not position), but order-non-preserving and surprising to hosts that assume positional alignment.
- The `run` `Done` arm now matches every `MachineOutcome` variant explicitly (`Completed`, `MaxTurnsExceeded`, `Cancelled`, `Failed`) instead of using a wildcard `other => ... unwrap_or(Cancelled)` fallback. `MachineOutcome` is `#[non_exhaustive]` but defined in this crate, so the compiler proves this exhaustive — a future variant forces a compile error here rather than being silently mislabelled as `Cancelled`.
- `handle_call_tools` doc corrected to state where cancellation is actually honored (the in-flight tool call is raced against the cancel signal in `execute_tool_call`'s `select!`; the sequential path checks the signal between calls), instead of claiming a `select!` that does not exist in the function itself.
- `set_token_counter` doc corrected — no longer claims a sync with `ContextManager` that the code doesn't perform. The driver field is documented as a fallback used only when no manager is configured.
- `ModelSwitch` doc corrected — removed stale "max-tokens" reference (the builder only has `context_window`).
- `MAX_RECOVERY_ATTEMPTS` doc rewritten — states the one-knob design (strategy sees the same ceiling the driver enforces) instead of implying two independent limits.
- `dispatch_tools_parallel` doc now documents hard-error semantics: a hard error from any call in a wave discards sibling results.

## [0.2.1] - 2026-08-04

### Fixed

- Detection-layer long-tail correctness (six items): `check_file_reads` now normalizes the query under the recorded op's real tool name (was: empty string) and matches by bidirectional path containment (was: exact equality), and rejects empty normalized params (an empty string is a substring of every query, which would inflate the read count); `LoopDetector::new` clamps `window_size == 0` to 1 with a warning; `find_best_match` rejects zero-score candidates even at threshold 0.0 and breaks ties lexicographically; `ToolShield::with_thresholds` swaps inverted warn/block pairs with a warning and rejects non-finite (NaN/inf) values, falling back to the band's default — a stored NaN would silently disable the band because every `score >= NaN` comparison is false. All non-breaking.
- `SessionConfig::compact_threshold` now clamps into its documented `0..=100` range on the validating construction paths (`Default`, `with_compact_threshold`, and `Deserialize`). Previously only the `with_compact_threshold` builder clamped; deserialized configs could carry an out-of-range value (e.g. `200` from disk), which the compaction subsystem would then interpret as "never compact." A single canonical clamp method plus a field-level serde deserialize helper now enforce the range silently. `Default` was already in range (80); its clamp call is defensive. Direct public struct-literal construction (`SessionConfig { compact_threshold: 200, .. }`) still bypasses normalization — the field is `pub`, and callers using that form are responsible for honoring the documented range. Non-breaking (silent clamp; no signature changes).
- `TokenBucket` refill clock no longer jumps to a future instant. The shared `elapsed_refill` helper advances `last_refill` only to the fill point (the instant capacity is reached) instead of to `at`, so a caller that passes a far-future instant — directly or via `take`/`acquire`/`available` — can no longer freeze the refill clock on the production rate-limit path. Non-breaking (callers passing correct `Instant::now()` values see no change).
- Corrected the `ParallelMode::Parallel` doc, which falsely claimed detection/observer side-effects "are not thread-safe" and fire "once on the final result only" in parallel mode. They are thread-safe (`DetectionManager` and the observer registry use `Mutex`/immutable-`Vec` interiors; `ToolHealthRegistry` uses atomics) and fire on every retry attempt in both modes, exactly as the code already does. No behavior change; the code matched the corrected doc all along.
- Fixed code-level doc contradictions: the `ApiClient` trait example showed `request: StreamRequest` (by-value) instead of `&StreamRequest` (matches the real trait), and `BareLoop::machine` was described as an "empty placeholder" rather than the real "empty machine (no history, no pending messages)".
- Reconciled the planning docs (ROADMAP, CONTEXT, ARCHITECTURE, README, DEPENDENCIES, DCH-DESIGN, the v0.2.0 release file) to the shipped 0.2.0 reality: status Planned→Shipped, `compact_threshold` u16→u8, `Loop::process_turn` soft-deprecated→removed, `LoopRuntime`/`LoopConfig`/`SessionResult`/`run_session` → their shipped replacements (`managers`/`SessionConfig`+`RunConfig`/`Run`+`Session`/`run`), MSRV 1.85→1.94, doctest count 303→286. Added a staleness banner to `LOOPCTL-DESIGN.md`.
- Restored the no-`#[allow(clippy::*)]` lint contract. Fixed: a private `TextStreamer` type alias, lossless integer-to-float casts (centralized in an internal `numeric` module), `PartLane`/`TerminalStage` lane enums replacing bool fields, and stale-allow deletions. No public API change.
